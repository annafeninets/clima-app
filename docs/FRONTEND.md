# Frontend

Статический frontend без UI-фреймворка и без сторонних npm-зависимостей. Используются нативные ES-модули, адаптивная вёрстка и Service Worker для Web Push.

## Быстрый старт (локально)

Сначала запустите backend, затем в отдельном терминале:

```bash
uv run python -m http.server 5173 --directory frontend
```

Откройте `http://localhost:5173`.

Если frontend открыт с другого origin, чем API, добавьте его в `CLIMA_CORS_ORIGINS` на backend и перезапустите сервер.

В Docker frontend отдаётся через nginx и проксирует `/api/` на backend (см. `docker.md`) — CORS в этом случае не требуется.

## Конфигурация

В Docker файл `config.js` создаётся при старте контейнера скриптом `nginx/40-clima-config.sh` из переменных окружения:

```js
window.CLIMA_CONFIG = {
  apiBaseUrl: "/api",           // CLIMA_PUBLIC_API_URL
  vapidPublicKey: "..."         // CLIMA_VAPID_PUBLIC_KEY
};
```

При локальной разработке можно создать `frontend/config.js` вручную.

## Реализованный функционал

| Область | Возможности |
|---|---|
| Авторизация | Регистрация, вход, выход |
| Профиль | Местоположение, тема (светлая/тёмная), настройки уведомлений |
| Гардероб | CRUD вещей, загрузка фото, статус стирки, индикатор комплектности |
| Подбор | Образы по погоде на сегодня / выбранную дату и место, до 3 вариантов |
| Оценка | Оценка надетых образов, история |
| Избранное | Сохранение, редактирование, замена вещей, создание своего комплекта |
| Push | Ежедневное уведомление «Утренний аутфит» в выбранное время |

Служебные маршруты (`/health`, `/internal/*`) намеренно не доступны из UI.

## Web Push

Требования:

- HTTPS (или `localhost`);
- на backend заданы `CLIMA_VAPID_PRIVATE_KEY` и `CLIMA_VAPID_SUBJECT`;
- публичный ключ передан во frontend (`CLIMA_VAPID_PUBLIC_KEY` → `config.js`).

Приватный ключ **никогда** не должен попадать во frontend.

Поток:

1. `src/features/push.js` регистрирует `service-worker.js`.
2. Разрешение на уведомления запрашивается только по явному действию пользователя.
3. Подписка + выбранное время и часовой пояс отправляются на backend (`POST /push/subscribe`).
4. Backend сохраняет данные в PostgreSQL и доставляет уведомление фоновым планировщиком.
5. Отключение — `DELETE /push/subscriptions`.

Особенности:

- если для комплекта не хватает обязательных вещей, отправляется отдельная подсказка (без отметки «аутфит уже отправлен»);
- повторные подсказки блокируются на день (Redis-флаг);
- переход по уведомлению о недостающих вещах открывает `/wardrobe?missing=...` с быстрыми кнопками добавления категорий;
- `/wardrobe/status` используется на страницах настроек и гардероба для отображения актуальной комплектности.

## Автодополнение городов

Реализовано для полей местоположения на странице планирования наряда и в настройках профиля.

Поведение:

- при фокусе на пустом поле показываются города по умолчанию для страны пользователя;
- при вводе — debounced поиск;
- навигация клавиатурой: ↑/↓ — выбор, Enter — подтверждение, Esc — закрытие списка;
- выбранный город подставляется в поле.

Источник данных:

- локальный `cities.json` + `citySearch.js`;
- страна пользователя определяется через `useUserCountry.js` (localStorage → язык браузера → `'RU'` по умолчанию).

Старый `<datalist>` для поля местоположения удалён, чтобы не конфликтовать с кастомным автодополнением.

## Страницы и состояние

Глобальное состояние (`src/core/state.js`) хранит:

- токен сессии;
- текущую страницу (`home`, `plan`, `wardrobe`, `favorites`, `history`, `settings`);
- профиль, локацию, тему;
- гардероб и его статус комплектности;
- текущие образы, избранное, ошибки.

Роутинг — client-side, без истории браузера (переключение страниц через состояние). При 401 токен сбрасывается и пользователь возвращается на экран авторизации.

## Стили и темы

- Адаптивная вёрстка в `styles/main.css`.
- Светлая и тёмная темы переключаются через `document.documentElement.dataset.theme`.
- Тема сохраняется в настройках пользователя на backend.

## Service Worker

`service-worker.js` отвечает за:

- приём push-событий;
- отображение уведомлений с иконкой и badge;
- обработку клика по уведомлению (переход в приложение).

Кэш статики Service Worker намеренно минимален — основной упор на корректную доставку push.
